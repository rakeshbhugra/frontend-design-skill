The system

Agents write the code. Seniors decide what ships.

Every engagement runs on the same three rules. They are why the speed holds up in production, not just in the demo.

  1. 01

    A human senior reviews every merge

    Agents open the pull request with the diff, the tests, and a written rationale. Nothing reaches main until a named engineer has read it and signed it.

    artifact: PR with rationale, reviewer name, review time
  2. 02

    Tests are written before the feature

    Day two produces the test plan. Agents build against it, so "done" is a green suite you can run yourself, not a screenshot in a status update.

    artifact: test plan, runnable suite, coverage report
  3. 03

    You own the repository from day one

    We work in your GitHub organisation, on your infrastructure, under your access controls. When the week ends, nothing has to be handed over because it was never ours.

    artifact: your repo, your CI, your deploy keys

A build week

Five days. One shipped increment.

Each week has the same shape. You see the plan on Monday, the tests on Tuesday, and running software on Friday.

  1. Mon

    Scope

    A 90-minute session turns the brief into one increment with a written definition of done.

    out: scope doc, signed
  2. Tue

    Plan the tests

    Architecture notes and the test plan go into the repo. You can object before a line of feature code exists.

    out: test plan, ADRs
  3. Wed

    Build

    Agents implement against the tests in parallel branches. Seniors review and merge through the day.

    out: merged PRs, green CI
  4. Thu

    Harden

    Load, failure, and rollback paths are exercised on a staging deploy that matches production.

    out: staging URL, runbook
  5. Fri

    Ship

    Production deploy, a recorded walkthrough, and a plain-language changelog. Then we scope the next week or stop.

    out: live release, changelog

30 days of fixes after the last week
